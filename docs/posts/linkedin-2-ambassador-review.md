어제 [["아무거나" 프로젝트]](← 글1 LinkedIn URL) 글에 "GPT-4o 두고 왜 굳이 Kanana-o냐" 댓글이 꽤 왔다.

답이 길어져 따로 정리한다. 카카오 AI 앰배서더로 **한 달 가까이 직접 코드에 녹여본 후기**다. 그 기간 안에 **음성 대화(모드 A) + 메뉴판 Vision(모드 B) + 멀티턴 컨텍스트 + 결정 유형 카드**까지 풀 구현했고, 그 과정에서 부딪힌 DX 디테일도 정리한다.

🎙️ 다른 점 1 — 톤 분기 코드를 짤 필요가 없었다

가장 인상 깊었던 부분. **사용자 음성이 피곤하면 응답 음성도 부드럽게 나온다.** 코드로 제어하지 않는다. **DPO 학습 효과로 모델이 알아서 감정 미러링**을 한다.

처음엔 "감정 분석 → 분기 → 톤 선택" 100줄짜리 로직을 짜려 했다. 막상 시스템 프롬프트 4줄만 넣어보니 모델이 알아서 했다.

```
5. 감정/의도 이해는 본문에 자연스럽게 녹여라.
   예) "지금 좀 지쳐 보이는데, 따뜻한 칼국수 어때요?"
   예) "오, 들떠있네! 매콤한 거 한 번 도전해볼래?"
```

📁 lib/features/chat/data/prompts/mode_a_prompt.dart

GPT-4o로 같은 걸 시도했을 때 응답 텍스트는 비슷했지만 **음성 톤은 평이**했다.

---

🍜 다른 점 2 — 옴니모달이 멀티턴을 단순하게 만든다

같은 모델이 음성·이미지·텍스트를 다 처리하니까, **모드 A의 맥락이 모드 B로 자연스럽게 이어진다.** 구현은 같은 messages 배열에 다 넣는 것.

```dart
'content': [
  {'type': 'image_url',
   'image_url': {'url': dataUrl}},
  {'type': 'input_audio',
   'input_audio': {'data': b64, 'format': 'wav'}},
  {'type': 'text',
   'text': '아까 빨리 먹어야 한다고...'}
]
```

📁 lib/features/chat/data/repositories/chat_repository.dart

비전+음성을 별도 모델로 붙이는 구조라면 모달 간 컨텍스트 옮기는 코드를 한참 짜야 한다. 단일 모델이라 이게 통째로 사라진다.

---

🗣️ 다른 점 3 — 한국 발화의 미묘한 것들

같은 음성을 두 모델에 직접 넣어봤다.

▸ 피곤한 톤 "아무거나"
   → Kanana-o: "지쳐 보이네요" 미러링
   → GPT-4o: 액면 그대로

▸ "뭐 먹을라꼬?" (경상도)
   → Kanana-o: 사투리 그대로 인식
   → GPT-4o: "뭐 먹을라고" 표준어 정정

한국 사용자 대상 프로덕트라면 이 차이가 결정적이다.

---

🔧 부딪힌 DX 디테일 3가지

**1. 오디오 16kHz 리샘플링**

Kanana-o가 16kHz mono WAV를 요구해서 클라이언트에서 맞춰야 한다. macOS에선 record 패키지의 sampleRate 옵션이 일부 무시돼 헤더와 실제 데이터가 어긋난 적이 있어 한참 헤맸다. 결국 `AudioEncoder.wav`로 패키지가 직접 WAV 헤더를 쓰게 우회.

(이 부분은 카카오 팀도 인지하고 있고 입력 포맷 유연 확장 계획 중인 것으로 들음)

**2. 음성 모달리티에서 메타 태그 누락**

시스템 프롬프트로 `[DECISION]` `[USER_HEARD]` `[EMOTION]` 같은 메타 태그를 강하게 요구해도, 음성 응답에서는 일관성이 떨어진다.

→ **룰베이스 폴백** (사용자 발화 + AI 응답 키워드 매칭) + **받아쓰기 단일 목적 호출 폴백** (USER_HEARD 누락 시 단일 모달리티로 재호출)을 같이 돌려 보강했다. 단일 호출은 다른 작업과 안 섞여서 형식 일관성이 훨씬 높다.

**3. 컨텍스트 16K**

음성·이미지가 토큰을 빨리 먹어서 멀티턴 길어지면 답답해진다. 슬라이딩 윈도우로 **최근 4턴**만 유지하는 식으로 잘라내야 안정적이다.

📁 lib/features/chat/presentation/providers/chat_provider.dart
